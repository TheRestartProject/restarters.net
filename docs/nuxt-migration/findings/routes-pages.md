# Findings: routes-pages

## Summary
routes/web.php (479 lines) defines ~130 individual URI registrations across two middleware wrappers: `ensureAPIToken` (public + guest-mixed) and `auth,verifyUserConsent,ensureAPIToken` (authenticated app). There is no route-level 'admin' middleware — admin gating is done inside controllers via `Fixometer::hasRole(Auth::user(),'Administrator')` returning `redirect('/user/forbidden')`, so a Nuxt SPA must replicate this as a client-side role check plus a server-side 403 from the API. 220 Blade views exist under resources/views; the shared layout `layouts/app.blade.php` loads jQuery/Bootstrap4/Moment/Leaflet/ekko-lightbox from CDNs, injects CSRF meta, GDPR cookie script, Matomo analytics, and conditionally includes `header`/`header_plain`/`navbar`/`footer`/onboarding-modal partials — none of this exists once the SPA is separate. 8 controller imports (DeviceUrlController, FaultcatController, MobifixController, DustupOraController, BattcatOraController, MobifixOraController, PrintcatOraController, TabicatOraController) are dead/unused — their former URL prefixes now just redirect via inline closures to a Discourse forum thread.

## Key facts
- routes/web.php has 3 top-level middleware groups: `ensureAPIToken` only (lines 46-258, public/guest pages), `auth+verifyUserConsent+ensureAPIToken` (lines 260-427, logged-in app), and a second `ensureAPIToken`-only group (lines 429-471, iframe/legacy stat endpoints + misc).
- Auth::routes() (vendor/laravel/ui AuthRouteMethods::auth()) expands to: GET/POST /login (Auth\LoginController@showLoginForm/login), POST /logout, GET/POST /register (Auth\RegisterController — effectively dead since app redirects /register -> /user/register), GET /password/reset + POST /password/email + GET /password/reset/{token} + POST /password/reset (Auth\ForgotPasswordController / ResetPasswordController), GET/POST /password/confirm (Auth\ConfirmPasswordController, requires 'auth'). No email verification routes.
- Middleware aliases (app/Http/Kernel.php): auth=Authenticate, guest=RedirectIfAuthenticated, verifyUserConsent=VerifyUserConsent, AcceptUserInvites=AcceptUserInvites (dashboard only), ensureAPIToken=EnsureAPIToken.

## Risks
- Route name collision risk: 'group.show' (group/view/{id}) is a custom name — verify with `php artisan route:list` inside Docker (not run here) rather than relying solely on static grep, since this session is on a Windows host per CLAUDE.md dev warning.
- Numerous GET routes perform mutations (markAsRead, group/delete/{id}, group/image/delete, party/deleteimage, party/join/{id}, brands/delete/{id}, skills/delete/{id}, tags/delete/{id}) — porting to REST/JSON conventions changes these to POST/DELETE, so any bookmarked/linked URLs, emailed invite links, or partner-site iframe src attributes pointing at these GET endpoints need auditing before cutover.
- The outer 'ensureAPIToken' group (lines 429-471) exposes /admin/stats/1 and /admin/stats/2 with NO auth middleware at the route level — only relying on whatever internal check AdminController::stats() does (not verified in this pass); candidate security/parity gap worth checking against adv-sec's findings.
- Legacy redirect blocks (FaultCat/MobiFix/etc., 16 blocks) reference 8 controller classes that are imported but entirely unused — safe to delete on cleanup, but confirm no other route file (routes/api.php, routes/console.php) references them before removing the classes.
- DashboardController index view name not fully confirmed (grep showed multi-line `return view(` at DashboardController.php:72 without capturing the string argument) — needs a follow-up Read before finalizing.
- UserController@getThumbnail's exact response type (binary image vs JSON) was not confirmed — matters for whether it stays server-side or becomes a plain <img src> against an API/S3 URL.
- Possible redundant/legacy auth flow: both Laravel-ui default /password/reset routes and custom UserController@reset/recover exist; unclear which is actually linked from the UI without checking Blade templates or the front-end code — risk of porting a dead flow into the new API design.

## Recommendations
- Treat resources/views/layouts/app.blade.php + header.blade.php as the single source of truth for global page chrome (CSRF meta, CDN script tags, Matomo, GDPR cookie script, GTM) that the Nuxt app.vue/nuxt.config.ts must reproduce or intentionally drop (e.g. dropping jQuery/Bootstrap4 CDN tags in favor of bootstrap-vue-next).
- Classify every 'admin-gated in-controller' route (Brands, Skills, Tags, Role, Category edit, Admin stats, PreviewDeploy) into a single Nuxt route-meta `requiresRole: 'Administrator'` pattern backed by corresponding API middleware/policy, replacing scattered `Fixometer::hasRole(...) -> redirect('/user/forbidden')` calls with consistent 403 JSON responses.
- Keep ExportController, CalendarEventsController, OutboundController (iframe/json branch), the /group/stats, /group-tag/stats, /party/stats/wide, /admin/stats/1 /admin/stats/2 widget endpoints, and MapsProxyController resident in Laravel as the API-only server's permanent server-rendered/proxy surface — consumed by non-SPA clients and out of scope for Nuxt page replication.
- Retire the 16 dead legacy-redirect route blocks and their 8 unused controller imports by moving them to a static web-server redirect map (nginx/Caddy) rather than porting into the new architecture.
- Consolidate the numerous single-purpose POST /profile/edit-* endpoints into a smaller set of RESTful PATCH /api/users/{id} (partial-field bodies), or mirror them 1:1 as named API actions if per-field validation granularity from the current Blade UX must be preserved in v1.
