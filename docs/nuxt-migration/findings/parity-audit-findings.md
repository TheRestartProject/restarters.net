## HIGH
### `/fixometer` — auth-gating
**SPA declares /fixometer public with no auth gate, but legacy required login to view the page at all, and the live site still redirects anonymous visitors to /login.**
- **Legacy:** git show 07e6abd7cc^:routes/web.php lines 273-334: `Route::prefix('fixometer')->group(function () { Route::get('/', [DeviceController::class, 'index'])->name('devices'); });` is nested inside the outer `Route::middleware('auth', 'verifyUserConsent', 'ensureAPIToken')->group(...)` opened at line 273. Anonymous requests are redirected to /login by the 'auth' route middleware before DeviceController::index() ever executes - the controller's internal Auth::id()-nullable guest-tolerant logic (git show 07e6abd7cc^:app/Http/Controllers/DeviceController.php lines 30-31) is unreachable when logged out. The Blade view (git show 07e6abd7cc^:resources/views/fixometer/index.blade.php) also `@extends('layouts.app')`, the full-navbar authenticated layout, not header_plain, consistent with this being an auth-gated app page.
- **SPA:** client/app/pages/fixometer.vue has no definePageMeta() call anywhere in the file (grep for definePageMeta returns nothing), so client/app/middleware/auth.global.ts:19-21 (`const requiresAuth = to.meta.auth === true; ... if (!requiresAuth) { return }`) never gates it - the page is fully public. The page's own doc comment (fixometer.vue:13-14) asserts 'Public, no auth gate - DeviceController::index() works for guests too', which is contradicted by the route-level 'auth' middleware in the legacy source that runs before the controller is ever invoked.
- **Live check:** curl -sS -o /dev/null -w '%{http_code} %{redirect_url}' https://restarters.net/fixometer -> 302 https://restarters.net/login (confirmed logged out; also confirmed for the trailing-slash form /fixometer/).
- **Fix:** Add `definePageMeta({ auth: true })` to client/app/pages/fixometer.vue to match legacy's route-level auth gate, and correct/remove the misleading doc-comment justification at lines 9-14 that currently asserts the page is intentionally public.

### `/group/edit/{id}` — missing-content
**Legacy's separate, NetworkCoordinator-accessible "Archive group" action is entirely absent from the SPA; its "Delete group" button silently calls the archive endpoint instead of performing a real delete, while keeping the old delete wording.**
- **Legacy:** Legacy exposed two distinct, differently-permissioned, differently-worded actions: (1) `GroupController::delete` (routes/web.php, GroupController.php:479-511) — a real hard delete, Administrator-only (`Auth::user()->hasRole('Administrator')`), force-deletes all the group's events and event-user rows; labelled `groups.delete_group` = "Delete group", confirm text `groups.delete_group_confirm` = "Please confirm that you want to delete :name." ### `/party/duplicate/{id}` — auth-gating
**The SPA's client-side canDuplicate check is stricter than legacy's userHasEditPartyPermission: NetworkCoordinators of the source event's group's network are shown a 'forbidden' message and cannot duplicate the event, even though legacy would have permitted it.**
- **Legacy:** routes/web.php:392 (git show 07e6abd7cc^) gates GET /party/duplicate/{id} inside the auth-verified party prefix group; PartyController::duplicate (git show 07e6abd7cc^:app/Http/Controllers/PartyController.php:281-284) calls `Fixometer::userHasEditPartyPermission($id, $user->id)` and redirects to /user/forbidden if false. That helper (git show 07e6abd7cc^:app/Helpers/Fixometer.php:115-145) returns true for: Administrator (line 130-132), OR a NetworkCoordinator who coordinates any network the event's group belongs to (lines 134-140), OR a Host of the event's group (line 142-144).
- **SPA:** client/app/pages/party/duplicate/[id].vue:34-40 computes `canDuplicate = isAdmin || (sourceEvent.group && hostedGroupIds.includes(sourceEvent.group.id))`, where `hostedGroupIds` is filtered from dashboardStore's `your_groups` to `role === HOST_ROLE (3)` only (line 35-37). There is no NetworkCoordinator branch at all - a user who is a NetworkCoordinator of the group's network but not personally a Host of that specific group sees the `party-duplicate-forbidden` alert (lines 109-116) instead of the duplicate form, where legacy would have let them through. The page's own comment (lines 10-19) acknowledges this is a deliberate 'safe false-negative' approximation, consistent with the identical limitation on /party/edit/[id].vue and documented project-wide in docs/nuxt-migration/api-gaps.md (section C4, ~lines 463-486) as unavoidable without a client-checkable 'is NetworkCoordinator of this group's network' signal.
- **Fix:** This is a known, consistently-applied, documented limitation (not unique to this page) stemming from no API exposing per-network coordinator membership client-side (api-gaps.md C4). Flagging for completeness of the parity audit; resolving it would require either a new/extended API field (e.g. dashboard your_groups including network-coordinated groups, or an explicit `canEdit`/`permissions` flag on the event resource) that this client could consume - same fix as would be needed for /party/edit/[id].vue.

### `/networks` — layout

- **Legacy:** Legacy gate: app/Http/Controllers/NetworkController.php (07e6abd7cc^) index() does `if (!$user->hasRole('NetworkCoordinator') && !$user->hasRole('Administrator')) abort(403);` inside the auth-only route group (routes/web.php:353), so this only fires for an already-authenticated user.
