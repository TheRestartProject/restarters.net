# Findings: vue-components

## Summary
Inventoried resources/js/app.js and all 134 files under resources/js/components (120 .vue components + 14 .test.js). The app mounts one independent Vue 2.7 root per DOM node carrying class 'vue' via a fixed lowercase-tag component map in app.js:394-430, sharing a single Vuex store; Blade passes data as string-interpolated props (`:prop=\"{{ $expr }}\"`, Eloquent __toString or json_encode, booleans as 'true'/'false' strings) rather than @json. Two domain mixins (event.js, group.js) plus a globally-applied i18n mixin (lang.js, Vue.mixin) form the real data/behavior backbone that most of the 120 components depend on via idevents/idgroups props and Vuex getters, with an explicit newToOld() adapter in several store modules translating /api/v2 response shapes back to legacy field names. Notable Vue2-only surface to port: 10 files using `.sync`, 11 files using legacy `slot`/`slot-scope`, one `Vue.set()` call, and Vue2-only npm packages (bootstrap-vue, vue-awesome, vue-multiselect, vue2-leaflet, vue2-editor/Quill, vue2-dropzone, vuelidate v0) each needing a Vue3-compatible replacement decision.

## Key facts
- Manual mount mechanism: app.js:394-430 does window.jQuery('.vue').each(function(){ new Vue({el:this, store, components:{...27 lowercase-key mappings...}}) }) -- one independent Vue 2 root per DOM node with class 'vue', all sharing one imported Vuex `store` singleton. This is the pattern that must be replaced by Nuxt pages/layouts + a single app root.
- Blade->prop encoding: no @json directive used anywhere found; pattern is `:prop-name="{{ $phpExpr }}"` where $phpExpr is either a raw scalar, an Eloquent model relying on its __toString/JsonSerializable (e.g. `:initial-group="{{ $group }}"`), or `json_encode($collection, JSON_INVALID_UTF8_IGNORE)`; booleans passed as literal 'true'/'false' strings e.g. `:canedit="{{ $can_edit_group ? 'true' : 'false' }}"`. Examples: resources/views/group/view.blade.php:142-157, resources/views/events/view.blade.php:109-124, resources/views/dashboard/index.blade.php:41-56.
- Vue.mixin(lang) in app.js:90 applies global i18n mixin adding this.__(key, values) and this.$lang.{get,choice,getLocale} to EVERY component instance app-wide; translations sourced at build time via Vite's laravel-translator plugin into import.meta.env.VITE_LARAVEL_TRANSLATIONS, keyed by document.documentElement.lang.
- Two domain mixins (mixins/event.js, mixins/group.js) are the primary 'data fetching' mechanism for ~40+ leaf/child components: components declare `idevents`/`idgroups` as their only required prop and pull everything else reactively from Vuex getters `events/get`/`groups/get` (and attendance/volunteers modules) rather than receiving full objects as props or calling axios themselves.
- Vuex store modules (auth, attendance, devices, events, groups, volunteers, networks, items, alerts) each own their own axios calls; events.js/groups.js/devices.js contain an explicit `newToOld(e)` adapter converting new-style `/api/v2/*` JSON (id, title, stats.volunteers, group.id) into legacy field names (idevents, venue, idgroups) the Vue tree still expects -- flagged as a compatibility shim to resolve during the Nuxt port.
- Auth token flow is cookie + query-string based, not header-based: apiToken read from `restarters_apitoken` cookie via vue-cookies in mixins/auth.js, stored in Vuex `auth/apiToken`, then manually appended as `?api_token=...` on most /api/v2 GET/POST/PUT/DELETE calls; CSRF token separately read from `<meta name=csrf-token>` and auto-attached to all axios requests as `X-CSRF-TOKEN` header in resources/js/bootstrap.js.
- Several legacy non-versioned POST routes are still called directly (not /api/v2): /party/update-quantity, /party/update-volunteerquantity, /party/remove-volunteer, /party/delete/{id}, /device-url -- these will need equivalents on the API-only Laravel backend or migration to /api/v2.
- No genuine Vue 2 `filters:` option exists anywhere in resources/js/components -- initial grep hits were false positives on components that merely have a prop literally named `filters` (Boolean). Confirmed via GroupEventScrollTable.vue and GroupEventsTab.vue source.
- No functional components (`functional: true`) and no custom event bus / `$root.$emit` pattern found; component communication is entirely props-down + Vuex getters, plus native `$emit` for child->parent and `.sync`/`v-model:x` for two-way bindings.
- Vue2-only constructs needing explicit porting: `.sync` modifier (10 files: StatsShareModal, GroupMapAndList, EventAddEdit, EventDevice, GroupAddEdit, FixometerFilters, FixometerPage, GroupMap, GroupsTable, GroupEventScrollTable) -> Vue3 `v-model:propName`; legacy unnamed `slot="name"` + `slot-scope="..."` syntax (11 files: EventImageModal, EventInviteModal, FixometerRecordsTable, DeviceImageModal, CalendarAddModal, GroupInfoModal, GroupsTable, GroupEventScrollTable, EventAddVolunteerModal, ConfirmModal, StatsShareModal) -> Vue3 `#name="scope"`; `Vue.set()` reactive-object-key pattern in NetworkData.vue -> plain assignment under Vue3 Proxy reactivity.
- vue2-only / soon-superseded npm packages actually consumed by components: bootstrap-vue ^2.22.0 (all `<b-*>` tags, 88 distinct usages across files) -> bootstrap-vue-next; vue-awesome ^4.1.0 (`<v-icon>`, only 3 icons imported: sync/save/check) -> replace with a Vue3 icon set; vue-multiselect ^2.1.6 (`<multiselect>`, used in DashboardAddData) -> check vue3 compat or swap; vue2-leaflet ^2.5.2 (LMap/LMarker/LTileLayer, GroupMap.vue) -> vue-leaflet/@vue-leaflet or Freegle's existing leaflet wrapper; vue2-editor (RichTextEditor.vue, wraps Quill 1.3.7 + quill-html-edit-button + quill-paste-smart) -> needs a Vue3-compatible WYSIWYG wrapper; vue2-dropzone ^3.6.0 (FileUploader.vue, dynamically imported) -> needs Vue3 dropzone wrapper or hand-rolled; vuelidate ^0.7.6 (EventAddEdit.vue, GroupAddEdit.vue `validations:` option-API blocks) -> @vuelidate/core for Vue3; vue-cookies ^1.7.4 (mixins/auth.js) -> check v4+ Vue3 support; leaflet-control-geocoder ^1.13.0 with Photon backend (GroupMap.vue, imports its own CSS) -> framework-agnostic, portable as-is.
- chart.js ^2.7.2 is listed in package.json but NOT imported/used anywhere in resources/js/components -- appears to be dead/legacy dependency, not part of the real component surface.
- app.js also retains large blocks of raw jQuery/DOM logic parallel to (and sometimes duplicating) Vue components: Google Places Autocomplete (raw `initAutocomplete()`/`fillInAddress()` in app.js vs. the separate PlacesAutocomplete.vue component), text truncation (`truncate()` jQuery function vs. ReadMore.vue component), Dropzone init for non-Vue upload forms (`loadDropzones()`), event-map Leaflet rendering for #event-map outside any Vue component (`eventsMap()`), and Bootstrap-based onboarding modal/slick carousel -- none of this is component-based and all of it needs a Nuxt-native (SFC-based) reimplementation, not a straight port.
- Test files present alongside components (Jest, 14 total): DeviceWeight.test.js, GroupInfoModal.test.js, GroupMap.test.js, GroupMapAndList.test.js, GroupMarker.test.js, GroupVolunteer.test.js, GroupWebsite.test.js, GroupsPage.test.js, GroupsRequiringModeration.test.js, GroupsTable.test.js, GroupsTableFilters.test.js, NetworkPage.test.js, plus store/groups.test.js -- useful as behavioral specs when porting to Vitest.

## Inventory
- **app.js entrypoint (/home/edward/restarters.net/resources/js/app.js)**: Not a component; boot file. Order: vendor.js -> bootstrap.js -> misc/notifications -> leaflet(+icon patch) -> constants -> Vue2.7 + BootstrapVue + IconsPlugin + Vuelidate + Vuex store + vue-multiselect + vue-awesome Icon registered globally as 'v-icon'/'multiselect'. Sentry.init inside the jQuery-ready block (DSN hardcoded, gated by window.restarters.analyticsCookieEnabled). Defines initializeJQuery() polling loop (50ms) waiting for window.jQuery and window.L before wiring ~30 legacy jQuery behaviors (popovers, dropzone uploads, onboarding modal/slick carousel, registration wizard steps, GDPR cookie notice, navbar hide-on-scroll, tab hash routing, Google Places Autocomplete for address fields, event map render via raw Leaflet). vue2-leaflet's LMap/LMarker/LTileLayer are registered globally via dynamic import() inside that same block.
- **Manual component mounting mechanism**: jQuery(".vue").each() creates a SEPARATE `new Vue({el, store, components:{...}})` root instance per DOM element carrying class 'vue' (resources/js/app.js:394-430). components map is a fixed dict of ~27 lower-case custom-tag-name -> imported .vue file (e.g. 'grouppage': GroupPage, 'eventpage': EventPage). Any Blade view that wants a Vue island wraps a custom element like <GroupPage ...> (PascalCase tag, Vue resolves via the case-insensitive map) inside a <div class="vue">. Multiple independent Vue roots per page is normal (not one SPA root) -> no shared root-level router/state beyond the single shared Vuex `store` instance imported into every root.
- **Server->client data encoding pattern**: Blade passes data as component props via string interpolation, NOT @json directive. Two forms seen: (1) `:idgroups="{{ $group->idgroups }}"` for scalars (2) `:initial-group="{{ $group }}"` relying on the Eloquent model's __toString()/JsonSerializable auto-JSON-encoding, and `:events="{{ json_encode($expanded_events, JSON_INVALID_UTF8_IGNORE) }}"` for arrays/collections built server-side into 'expanded' shapes. Booleans passed as literal 'true'/'false' strings via `:canedit="{{ $x ? 'true' : 'false' }}"`. Examples: resources/views/group/view.blade.php:142-157 (<GroupPage>), resources/views/events/view.blade.php:109-124 (<EventPage>), resources/views/dashboard/index.blade.php:41-56 (<DashboardPage>). csrf_token() is passed as a plain `csrf` prop on nearly every root component and consumed by the shared `auth` mixin.
- **mixins/auth.js**: Global-ish mixin (not Vue.mixin'd, imported per top-level page) declaring prop `csrf`; computed `apiToken` from `$store.getters['auth/apiToken']`; on created() reads api token from `restarters_apitoken` cookie via vue-cookies and dispatches `auth/setApiToken` + `auth/setCSRF` into Vuex. This is how API-token auth is bootstrapped client-side per Vue root.
- **mixins/event.js**: Shared computed properties for any component with an `idevents` prop: pulls the full event object from `$store.getters['events/get'](idevents)` and derives attending/volunteerCount/approved/upcoming/finished/inProgress/startingSoon/start/end/date/dayofmonth/month/timezone/attendees/confirmed/invited/participants/volunteers, using moment + moment-timezone with `moment.locale(this.$lang.getLocale())`.
- **mixins/group.js**: Shared computed properties for components with an `idgroups` prop: `group` from `$store.getters['groups/get']`, `volunteers` from `$store.getters['volunteers/byGroup']`, plus canedit/candemote/ingroup flags read off the group object.
- **mixins/lang.js (Vue.mixin, global)**: Applied globally via `Vue.mixin(lang)` in app.js. beforeCreate() sets `this.$lang = {get, choice, getLocale}`; adds instance method `__(key, values)` used pervasively in templates for i18n, backed by resources/js/mixins/lang-utils.js and translations sourced from `import.meta.env.VITE_LARAVEL_TRANSLATIONS` (Vite laravel-translator plugin output), keyed off `document.documentElement.lang`. Missing keys report to Sentry.captureMessage and fall back to the raw key.
- **mixins/images.js**: Trivial mixin exposing computed `imageUrl(path) => path` used only to dodge Vite's static-asset import-resolution during build (`:src="imageUrl('/images/x.svg')"`); no real transform. Irrelevant once ported to Nuxt's own asset handling.
- **mixins/map.js, mixins/co2equivalent.js, mixins/validationHelpers.js**: Not read in full detail; map.js is used by GroupMap.vue (bounds/zoom helpers), co2equivalent.js used by stats components for CO2 impact formatting, validationHelpers.js used alongside Vuelidate in EventAddEdit/GroupAddEdit forms.
- **Vuex store (resources/js/store/index.js)**: Single Vuex 3 store, namespaced modules: auth, attendance, devices, events, groups, volunteers, networks, items, alerts. Modules fetch from API and cache by id keyed under state.list; several modules (events.js, groups.js, devices.js) contain a `newToOld(e)` translation function converting the new `/api/v2/*` response shape (id, title, stats.*, group.id) back into legacy field names (idevents, venue, group.idgroups, volunteers) expected by existing components -- an explicit adapter layer that a Nuxt port should either retire (rename all consuming components to new field names) or reproduce as a Pinia store transform.
- **API endpoints called from store modules**: groups.js: GET /api/usersgroups/, GET /api/v2/moderate/groups?api_token=, GET /api/v2/groups/summary?locale=, POST/GET /api/v2/groups/{id}. events.js: POST /party/delete/{id} (legacy non-REST), GET /api/v2/moderate/events?api_token=, GET/POST/PUT /api/v2/events(/{id})?api_token=, GET /api/v2/groups/{id}. volunteers.js: /api/v2/groups/{id}/volunteers (GET/POST/DELETE variants). attendance.js: /api/events/{id}/... , POST /party/remove-volunteer (legacy). devices.js: /api/v2/devices(/{id})?api_token=, POST /device-url, DELETE /device-url/{id}. items.js: dynamic url GET. networks.js: GET /api/v2/networks. alerts.js: GET /api/v2/alerts.

## Risks
- The newToOld() adapter functions in store/events.js, groups.js, devices.js mean the current Vuex data shape consumed by ~120 components is NOT the same as the actual /api/v2 response shape; a naive 'point Nuxt at the same API' port will silently break unless the adapter logic is either preserved in a Pinia store layer or every consuming component/mixin is rewritten to the new field names.
- Auth model mixes cookie-read api_token (query-string auth) with CSRF-header session auth in the same app; an SPA-only client with a mobile Capacitor target eventually will need a single coherent token-based auth strategy (e.g. Sanctum SPA cookies won't work well in Capacitor) -- decide this early since ~9 store modules and NetworkPage.vue/GroupTimeZone.vue/Notifications.vue/DiscourseDiscussion.vue/EmailValidation.vue/EventAttendance.vue all hand-roll their own auth-header/query attachment.
- Legacy non-REST routes (/party/update-quantity, /party/update-volunteerquantity, /party/remove-volunteer, /party/delete/{id}, /device-url) are called directly from components/store and are NOT under /api/v2 -- these need explicit inventory on the Laravel side to decide whether to keep, alias, or migrate to versioned API endpoints before the Nuxt client can drop Blade entirely.
- Several components duplicate logic that also exists as raw jQuery in app.js (address autocomplete, text truncation) -- risk of behavioral drift/regressions if only one side is ported.
- vue2-editor, vue2-dropzone, vue2-leaflet, vuelidate are all Vue-2-specific packages with no guaranteed Vue 3 compatible drop-in; each requires an explicit replacement decision (this is the single biggest package-level porting risk block).
- NetworkPage.vue directly manipulates a Bootstrap jQuery modal (`window.$('#network-add-group').modal('show')`) from within a Vue component -- this DOM-coupling assumption (a Bootstrap 4/jQuery modal element existing elsewhere on the page, likely in Blade) breaks entirely once there is no server-rendered page shell; must be replaced with a bootstrap-vue-next `<b-modal>` before or during the API-only cut.

## Recommendations
- Treat mixins/event.js and mixins/group.js as the primary reusable 'data model' contracts to preserve (or reimplement as Pinia composables/store getters keyed by id) since ~40+ components depend on their exact computed-property names (attending, upcoming, finished, dayofmonth, month, canedit, candemote, ingroup, etc).
- Reimplement mixins/lang.js as a Nuxt i18n module (or a thin Pinia/composable wrapping the same translateWithLocale/choiceWithLocale logic in resources/js/mixins/lang-utils.js) so the `__()`/`$lang` API surface used in every template can stay largely unchanged, minimizing template edits.
- Resolve the newToOld() adapter question first: either (a) have the Nuxt Pinia stores keep an equivalent adapter so ported components/mixins need zero field-name changes, or (b) do a coordinated rename pass across all consuming components to the new /api/v2 field names as part of the port (cleaner long-term, larger diff).
- Decide the auth/token strategy up front given the future Capacitor target: prefer a header-based bearer token (e.g. Sanctum personal access token or Laravel Passport) stored in memory/secure storage over the current cookie+querystring api_token pattern, since query-string tokens leak into logs/URLs and cookies are awkward in Capacitor webviews.
- Audit and consolidate the ~5 legacy non-/api/v2 routes (/party/*, /device-url) called from the frontend; either version them under /api/v2 or explicitly whitelist them as retained legacy endpoints in the API-only Laravel design.
- Pick Vue3-compatible replacements before starting component ports for: WYSIWYG editor (replace vue2-editor, keep Quill 1.3.7 core + htmlEditButton + paste-smart if possible), file upload (replace vue2-dropzone), Leaflet wrapper (align with whatever Freegle's iznik-nuxt3 already uses for its map, likely more Nuxt/Vue3-idiomatic than vue2-leaflet), form validation (@vuelidate/core replacing vuelidate v0), icon set (replace vue-awesome's 3 icons with a Vue3 icon component).
- When porting the ~27 'root/page' components (list in inventory item 'Manual mount mechanism'), map each 1:1 to a Nuxt page/route; the ~90+ shared/child/leaf components map to resources/components structure largely unchanged in shape, but strip the mixins/auth.js prop-based csrf/apiToken bootstrapping in favor of a global Pinia auth store populated once at app init.
- Explicitly reconcile the duplicated jQuery-vs-Vue-component logic (Places Autocomplete, text truncation) by keeping only the Vue component version (PlacesAutocomplete.vue, ReadMore.vue) and dropping the parallel jQuery implementations in app.js during the port, since app.js itself is being retired.
- Preserve the 14 existing Jest test files as a starting spec set when writing the new Vitest suites; they encode expected component behavior (props/events/store interactions) independent of the Blade-hosting concerns.
