# Findings: playwright-regression

## Summary
Playwright suite lives at tests/Integration/ (7 spec files, ~1580 lines), config testDir tests/Integration, baseURL http://restarters_nginx (overridable via PLAYWRIGHT_BASE_URL env), single Chromium project, workers:1 (CSRF), retries:2, timeout 5min. It is almost entirely a full-stack UI flow suite hitting real Blade pages that mount Vue 2 islands (bootstrap-vue components: multiselect, b-calendar, b-modal, dropzone), plus a handful of raw page.request API assertions against /api/v2/*. Auth is via a shared login() helper posting the real login form; data seeding is done out-of-band by Taskfile.yml's docker:test:playwright task (php artisan tinker inserts fixed users/network/group before the suite runs), not by the tests themselves. Google Maps network calls are aborted in tests/Integration/fixtures.js to prevent hangs; a custom X-Playwright-Test header signals test mode to the backend for cache-bypass.

## Key facts

- Selector style across the whole suite: overwhelmingly CSS classes tied to current Blade/Vue markup (.tag-item, .create-tag, .edit-tag-btn, .delete-tag-btn, .modal.show, .tags-management, .device-info, .add-powered-device-desktop, .multiselect__option, .ql-editor, #group_name, #event_date, #tags) plus some text-based locators (hasText: 'Create group', 'Save changes', 'EVENT ACTIONS', 'Invite Volunteers') and a couple of id selectors (#fp_email, #password, #dropzone). ZERO data-testid attributes anywhere in the suite — every selector is coupled to either a hand-authored CSS class in Blade/Vue templates or Bootstrap/BootstrapVue/vue-multiselect/Quill/vue-dropzone's own generated class names (.multiselect__content-wrapper, .b-calendar-grid, .dz-preview, .custom-select)
- No spec file uses request-mocking/interception for API responses (only fixtures.js's Maps-abort and header-inject); all data flows through the real Laravel backend/DB per Taskfile seeding — this is a true black-box E2E suite, not a component/unit test layer
- grouptags.test.js has heavy reliance on page.waitForTimeout(500/1000/2000) fixed sleeps after Vue re-renders (multiselect filtering, save operations) rather than deterministic waits — a known flakiness/anti-pattern the migration should not carry forward as-is
- Some tests explicitly comment on distinguishing 'old Blade modal (removed)' vs 'new Vue component' (event.test.js line 51-53) — evidence the suite is already mid-migration-aware and encodes assumptions about which pages are Blade vs Vue

## Inventory
- **tests/Integration/landingpage.test.js**: 2 tests: static Blade homepage h2 text check; login() smoke test. No Vue dependency for the first test.
- **tests/Integration/legacyassets.test.js**: 2 tests: raw HTTP GET on /css/wiki.css and /global/css/app.css checking 200+CSS content-type. Infra test for MediaWiki asset compatibility, irrelevant to Nuxt SPA cutover except must keep these static paths served by Laravel/API host.
- **tests/Integration/group.test.js**: 3 tests: create group, create+unfollow group, group image upload persistence. Depends on createGroup/unfollowGroup helpers in utils.js; heavy Vue-form interaction (Quill RTE, timezone input, geocoding hack, vue-dropzone image upload).
- **tests/Integration/event.test.js**: 3 tests: create future/past event, invite-volunteers modal (BootstrapVue modal + vue-multiselect). Depends on createGroup/createEvent/approveEvent helpers; asserts POST /api/v2/events/{id} response.
- **tests/Integration/device.test.js**: 5 tests (1 excluded by default config grep): spare parts flag, misc powered device, device+photo upload, automatic category-suggestion autocomplete (slow, excluded). All chain login/createGroup/createEvent/approveEvent/addDevice helpers.
- **tests/Integration/grouptags.test.js**: 34 tests, largest file: NC/Admin/Host permission matrix for group tagging feature (create/edit/delete/duplicate-validation/assign-to-group/list-filter/display), plus 4 direct API tests (no UI) against /api/v2/networks/{id}/tags|groups|events|stats. Depends on getNetworkId/getGroupId helpers that query API for fixed seeded names.
- **tests/Integration/fixtures.js**: Custom Playwright 'test' fixture: injects X-Playwright-Test header to backend requests only, aborts all Google Maps network calls (JS/tiles) to avoid headless-Docker hang, sets window.PLAYWRIGHT_TEST=true. Imported by every spec via require('./fixtures') instead of @playwright/test directly.
- **tests/Integration/utils.js**: Shared helper library (376 lines): login, createGroup, createEvent, approveEvent, addDevice, addDeviceFast, unfollowGroup. Encapsulates all Blade+Vue form interaction sequences reused across specs; also has DEBUG-gated console logging via PLAYWRIGHT_DEBUG/DEBUG env vars.

## Risks
- Every test's selectors are CSS classes emitted by hand-authored Blade/Vue2/bootstrap-vue/vue-multiselect/Quill/vue-dropzone markup — none are data-testid based, so essentially 100% of locators will break or need re-verification when Blade views are deleted and re-implemented as Nuxt/Vue3/bootstrap-vue-next components, even where the same class names are reused by convention (bootstrap-vue-next may not replicate all class names of bootstrap-vue, e.g. .custom-select, .multiselect__* from vue-multiselect vs a different multiselect widget)
- Suite hits Laravel-rendered pages directly (page.goto('/group'), '/party/create', '/networks/{id}') and asserts on server-controlled state transitions like Blade->redirect->edit URL (waitForURL('**/edit/**')) — once the app is a client-routed Nuxt SPA these URL/redirect semantics must be replicated client-side (Nuxt Router) or the tests rewritten to assert on route path changes instead of full navigations
- Fixed sleeps (waitForTimeout 500-3000ms) scattered through utils.js and grouptags.test.js mask real async race conditions (Vue mount timing, geocoding autocomplete); porting to Nuxt's different hydration/mount timing may change these timings and produce new flakiness
- Test data seeding happens entirely outside the test files (Taskfile.yml tinker script) and is idempotent via firstOrCreate/insertOrIgnore but is coupled to Laravel Eloquent models/DB schema directly — if the Nuxt migration also changes API-only backend seeding strategy, this seeding step needs equivalent reimplementation reachable from whatever CI runs Nuxt e2e tests
- Google-Maps-abort logic in fixtures.js is baseURL-string-matched against 'http://restarters_nginx' — a hardcoded Docker-internal hostname; a Nuxt dev/test server will have a different origin and this matching logic needs updating alongside baseURL config
- grouptags.test.js's login+getNetworkId+getGroupId pattern makes GET calls to /api/v2/networks/ and /api/v2/groups/names before UI interaction, i.e. tests are not purely UI-driven — any API contract changes (auth token vs session cookie, response envelope body.data vs body) during the API-only Laravel conversion will break these helper functions first
- Playwright config pins workers:1 explicitly because of 'CSRF issues' with session-based Laravel auth; migrating to token-based SPA auth (JWT/Sanctum) may remove this constraint and could allow parallelization, but must be verified rather than assumed

## Recommendations
- Keep tests/Integration/fixtures.js's Maps-abort/header-inject strategy conceptually but generalize the baseURL matching (currently hardcoded to 'http://restarters_nginx') to work against whatever Nuxt dev/preview origin is used, and add an equivalent for any new API origin if Nuxt and Laravel run on different ports/hosts
- Migrate login() first and foundationally: switch from session-cookie form login (fills #fp_email/#password, waits for 'section.dashboard') to whatever Nuxt+Pinia auth flow replaces it (likely POST to an API login endpoint + token storage) — every other spec depends on login(), so this is the single highest-leverage helper to update, mirroring how Freegle's iznik-nuxt3 Playwright helpers likely centralize auth
- Introduce data-testid attributes into the new Nuxt components as they are built (group create/edit forms, event forms, device modal, tag management on network page) so this suite's ~90% CSS-class-selector debt doesn't reproduce; do this proactively per-component during migration rather than retrofitting after Nuxt cutover
- Recommended page migration order to keep the suite green incrementally: (1) landingpage.test.js and legacyassets.test.js first — these have zero/minimal Vue dependency and validate the static shell and legacy asset paths survive the framework swap; (2) group.test.js's createGroup flow next since createGroup() is a dependency of nearly every other spec (event, device, grouptags-via-group-edit) — stabilizing this unblocks the rest; (3) event.test.js next (depends on createGroup); (4) device.test.js (depends on createGroup+createEvent+approveEvent, includes the most complex Vue interaction — dropzone, multiselect, category autocomplete); (5) grouptags.test.js last — largest, most permission-matrix-heavy, and least critical-path (34 tests but a single feature), also currently laden with waitForTimeout anti-patterns worth rewriting to deterministic waits (waitForResponse) during the port rather than preserving as-is
- Rewrite the fixed waitForTimeout(500|1000|2000|3000) calls in utils.js and grouptags.test.js to waitForResponse/waitForSelector-based deterministic waits during the Nuxt port — this is a good forcing function since the API-only backend will make network-response-based waits (already used in approveEvent, group image upload, invite modal) straightforward to apply everywhere
- Keep the Taskfile.yml docker:test:playwright seeding step (jane@bloggs.net/nc@test.net/host@test.net, 'Test London' network, 'Tag Test Group' group) unchanged in spirit — it only touches the Laravel DB via Eloquent, independent of the frontend framework — but verify it still runs before the Nuxt Playwright pass in whatever new CI config replaces/augments task docker:test:playwright
- Preserve all existing spec file flows/URLs and login credentials as the acceptance-criteria contract (login as X, create group, create event, add device, verify stats/tags) — treat this document's test-by-test breakdown as the literal regression checklist the Nuxt app's Playwright suite (likely relocated under a Nuxt-side tests/ dir, matching Freegle's iznik-nuxt3 conventions) must reproduce test-name-for-test-name before old suite retirement
- For the 4 pure-API tests in grouptags.test.js (lines 425-478) and the getNetworkId/getGroupId helpers, no UI changes are needed at all — these can run against the API-only Laravel backend unmodified regardless of Nuxt frontend status, making them good 'always green' canaries during the transition
- Avoid big-bang cutover: given workers:1 and single-suite-file structure, plan to run the legacy Blade-flow suite and a parallel Nuxt-flow suite side by side (different baseURL) during migration, retiring each Blade-dependent spec file only once its Nuxt equivalent passes, rather than attempting one atomic swap of testDir
