# Findings: styles

## Summary
Restarters.net currently ships TWO parallel Bootstrap-4 design systems on every Fixometer page (resources/sass/app.scss and resources/global/css/app.scss, both @vite'd together in layouts/header*.blade.php), each compiling its own full Bootstrap 4 and its own brand-variable set with different values. resources/global/css is the umbrella brand layer already shared with the MediaWiki Wiki skin and is the better seed for the new Nuxt assets/css/ global stylesheet; resources/sass/* page-partials (_events, _groups, _host, etc.) should become page/component-scoped styles, and Wiki's stylesheet chain (and the legacyCssAliases vite hack it requires) dies with Blade since Wiki stays server-rendered. BS4-only markup (data-toggle/dismiss, .close, .sr-only, badge-*, form-group, input-group-append) appears in dozens of files and needs systematic BS5 renaming; bootstrap-vue usage is heavy (b-img 79x, b-btn 41x, b-img-lazy 27x, b-form-group 27x) with concrete gaps against bootstrap-vue-next (b-btn alias gone, b-img-lazy removed, b-form-datepicker has no equivalent) plus several Vue2/jQuery-only deps (vue-awesome, vue-typeahead-bootstrap, vue2-leaflet, select2-via-jQuery-shim, tempusdominus-bootstrap-4) that must be replaced rather than ported.

## Key facts
- Two (arguably three, counting wiki) fully separate SCSS design systems are compiled and shipped together on every Fixometer page: resources/sass/app.scss (legacy 'Fixometer' skin, $brand-blue #0faca8) and resources/global/css/app.scss (umbrella 'restarters.net' brand skin shared with Wiki, $brand #0394a6). Both @import a full copy of bootstrap/scss/bootstrap — i.e. Bootstrap 4 is compiled twice into the page bundle today.
- layouts/header.blade.php:41, header_plain.blade.php:38, header_nocookie.blade.php:23 all do @vite(['resources/sass/app.scss','resources/global/css/app.scss']) — confirms dual-stylesheet load on every page.
- resources/global/css/_navigation-bar.scss + resources/global/css/app.scss is the actual site-wide chrome (top nav, footer via wiki/layout/_footer, buttons, forms, tabs, cards, tables) reused across Fixometer app AND MediaWiki Wiki skin — this is the closest existing analog to what should become the new Nuxt app's assets/css/ global stylesheet.
- resources/sass/_navigation.scss and _footer.scss are a SEPARATE, older nav/footer implementation specific to the Fixometer Blade pages, not used by Wiki. Two navs exist today; migration should consolidate on the global/css one as the brand source of truth since it's the one already shared cross-product.
- resources/sass/_main.scss (device/repair-status sprites, party-images, h1-h3 base type) is never @imported by app.scss — verify at migration time whether it's genuinely dead or included by an untraced path; if dead, do not port it.
- $blue used throughout (_main.scss, _footer.scss, _navigation.scss via $blue) is never defined in the sass/ tree — it's implicitly Bootstrap 4's default theme color (#007bff), an invisible dependency that will silently shift (BS5 default $blue is #0d6efd) or vanish if Bootstrap's variable isn't imported first in the new stack.
- Google Fonts are loaded via CSS @import url(fonts.googleapis.com) in TWO places (sass/_variables.scss and global/css/app.scss) rather than <link rel=preconnect/stylesheet> or self-hosted — render-blocking and duplicated network request today; should become a single self-hosted or <link>-based load in Nuxt.
- Icon strategy is hybrid: inline Blade SVG partials (resources/views/partials/svg-icons/*.blade.php) for nav/UI icons, raster sprite sheets (resources/icons/*.png) referenced via CSS background-position for device repair-status/category icons, and vue-awesome (FontAwesome-as-Vue-component, no Vue3 build) inside .vue islands.
- BS4 attribute/class migration surface: data-toggle in 29 files, data-dismiss in 13, form-group in 49, class="close" in 10, badge-{variant} in 9, input-group-append/prepend in 4, sr-only in 4. No custom-control, jumbotron, or media-object usage found (zero-cost items).
- bootstrap-vue component surface in .vue files: b-img(79), b-btn(41), b-dropdown-item(38), b-img-lazy(27), b-form-group(27), b-button(23), b-input(18), b-tab family(20+), b-modal(12), b-alert(10), b-badge(6), b-form-datepicker(5). b-btn, b-img-lazy, and bare b-input/b-select aliases either don't exist or behave differently in bootstrap-vue-next and need rename/replacement, not 1:1 swap. b-form-datepicker has no bootstrap-vue-next equivalent — needs a different date-picker library entirely.
- vite.config.js's legacyCssAliases plugin exists solely to preserve unhashed /css/wiki.css and /global/css/app.css URLs that MediaWiki hardlinks — this constraint disappears once Wiki/Discourse remain server-side and only the Fixometer SPA moves to Nuxt, simplifying the new build (no legacy alias hack needed for the SPA's own CSS).

## Inventory
- **resources/sass/app.scss**: Main Fixometer app stylesheet entry, imported by @vite in layouts/header.blade.php, header_plain.blade.php, header_nocookie.blade.php. Imports _variables, full bootstrap 4 SCSS, bootstrap-vue.css, slick-carousel, tokenfield (+ _tfvariables), dropzone, select2 core, bootstrap4-datetimepicker (BS4-only build), bootstrap-sortable.css, leaflet, then ~50 partials (_navigation, _footer via _main? no — _footer/_navigation imported individually, _admin, _dashboard, _events, _groups, _host, _profile, _properties, _reporting, _networks, _user, _widget, _battcat, _onboarding, _steps, _slideshow, _volunteers, etc.).
- **resources/sass/_main.scss**: NOT imported by app.scss (dead/orphan file — grep shows no @import 'main' anywhere in app.scss). Contains body/h1-h3 typography, device/status/cluster sprite classes, party-images, .device-img hover zoom, .lng-switcher. Confirm before migrating — may be legacy dead code.
- **resources/sass/_variables.scss**: Brand tokens for the Fixometer skin: $body-bg #f5f8fa, $brand #222/$brand-black, $brand-orange #ffbe5f, $brand-blue #0faca8, $brand-grey #f5f7fa, $brand-pink #F49292, $font-family-sans-serif Asap, $font-family-second 'Open Sans'. Also directly @import url()'s Google Fonts (Open Sans 400/700, Patua One, Asap 400/700) — render-blocking external CDN call baked into CSS.
- **resources/sass/_mixins.scss**: Defines .Font-PatuaOne / .Font-OpenSans utility classes (used via @extend across _main, _footer, _host, _outbound) plus .orange, .clearfix, border-radius/transition mixins. $blue is NOT defined anywhere in resources/sass — it resolves to Bootstrap 4's default theme $blue (#007bff) via load order, an implicit/fragile dependency that breaks silently on BS5 migration (BS5 also defines $blue #0d6efd, close by luck) or Sass module changes.
- **resources/sass/_navigation.scss + _footer.scss**: Fixometer-app-specific navbar/footer chrome (#navigation, .nav-wrapper, #main-footer) — distinct from and NOT shared with resources/global/css navigation-bar. This is the 'old' header used on Fixometer-only pages.
- **resources/global/css/app.scss**: Second, separate design system ('global') entry, imported alongside app.scss in the same 3 header layouts and in footer.blade.php's JS. Its own _variables.scss ($brand #0394a6, $brand-light, spacer map 10-60px, $theme-colors map), its own full bootstrap/bootstrap.scss import (a second full BS4 compile — duplicate CSS payload), its own Asap Google Fonts @import, components/navigation-bar (the actual site-wide restarters top nav + dropdown), plus components/{alerts,buttons,dropdown,forms,modal,card-talk,tables,events-tables,custom-check-tick,lists,tabs,tabs-no-space-mobile,pagination,row-columns,cards}, helpers/hr, plugins/select2. This is the umbrella brand skin shared with the Wiki.
- **resources/wiki/css/app.scss**: Third entry (MediaWiki skin), built by Vite then copied via legacyCssAliases plugin to unhashed public/css/wiki.css (MediaWiki references it by fixed path, can't use hashed Vite output). @imports ../../global/css/variables and ../../global/css/bootstrap/bootstrap (a THIRD full BS4 compile) plus global/css/components/lists, then wiki-specific layout/_fonts, layout/_footer, components/{search-button,edit-page-button,row-arrows,alerts,lists}, and large .mw-parser-output / .mw-collapsible chapter-numbering rules for MediaWiki markup itself. Out of scope for Nuxt (Wiki stays server-rendered by MediaWiki) but its global/_variables and global/bootstrap dependency shows global/css is the true cross-product brand layer.
- **vite.config.js entries**: Five build inputs: resources/js/app.js, resources/sass/app.scss, resources/global/js/app.js, resources/global/css/app.scss, resources/wiki/js/wiki.js, resources/wiki/css/app.scss. Custom legacyCssAliases plugin copies wiki.scss and global/css output to fixed /css/wiki.css and /global/css/app.css because MediaWiki/legacy consumers hardlink those URLs — a constraint that disappears once Wiki is decoupled from the SPA.
- **Blade layout inclusion map**: layouts/header.blade.php, header_plain.blade.php, header_nocookie.blade.php each do @vite(['resources/sass/app.scss','resources/global/css/app.scss']) — i.e. EVERY Fixometer page loads both the app-specific stylesheet AND the global umbrella stylesheet (2x Bootstrap 4 compiled and shipped). layouts/footer.blade.php loads the JS pair. partials/visualisations/leaf.blade.php loads only resources/js/app.js (Leaflet map partial, likely embeddable/iframe use).
- **Icons**: Two systems: (1) resources/icons/ — raster+SVG sprite assets (Category_Icons-0X, cluster/status sprite sheets used via CSS background-position in _main.scss, .png sprites for repair-status icons); (2) resources/views/partials/svg-icons/*.blade.php — inline SVG partials (admin-cog-icon, calendar-icon, copy-icon, etc.) included directly into Blade markup, no icon font. JS side uses vue-awesome (Font Awesome icon set wrapped as Vue components, BS4-era, no Vue3 release) — 80 files reference icon-related patterns.
- **Fonts**: Asap (body/UI), Open Sans (body text via .Font-OpenSans), Patua One (headings via .Font-PatuaOne) — all loaded from fonts.googleapis.com via @import url() inside two different _variables.scss files (duplicate requests: sass/_variables.scss pulls Open+Sans/Patua+One/Asap, global/css/app.scss separately pulls Asap only). No self-hosted fonts, no font-display/preload strategy visible.
- **BS4-only patterns found**: form-group: 49 files. input-group-append/prepend: 4 files (needs input-group-text in BS5). badge-{variant}: 9 files (BS5 renames to text-bg-{variant}). data-toggle: 29 files (BS5 renamed to data-bs-toggle). data-dismiss: 13 files (BS5: data-bs-dismiss). class="close": 10 files (BS5: btn-close). sr-only: 4 files (BS5: visually-hidden). custom-control/jumbotron/media-object: 0 hits — not present, one less migration concern.
- **bootstrap-vue component usage (resources/js/**/*.vue)**: By frequency: b-img(79), b-btn(41, DEPRECATED ALIAS — bootstrap-vue-next has no b-btn, must rename to b-button), b-dropdown-item(38), b-img-lazy(27, REMOVED in bootstrap-vue-next, needs custom lazy-img or native loading=lazy), b-form-group(27), b-button(23), b-input(18, becomes b-form-input-only in bvn — bare b-input may not exist), b-td/b-th/b-tr/b-thead/b-tbody/b-table-simple(table primitives, present in bvn), b-tab/b-tabs(20), b-modal(12), b-alert(10), b-card family(9+6+2), b-badge(6), b-select(5, alias — bvn wants b-form-select), b-form-datepicker(5, NOT in bootstrap-vue-next — needs replacement, e.g. custom component or v-calendar), b-input-group/-append/-prepend(5), b-form-checkbox(2), b-collapse(2), b-pagination(1).
- **Non-bootstrap-vue JS deps with BS4/Vue2 coupling**: tempusdominus-bootstrap-4 + bootstrap4-datetimepicker (jQuery, BS4 CSS classes) — must be replaced (e.g. b-form-datepicker/vuejs-datepicker/flatpickr) for Vue3+BS5. select2 (jQuery-based, works via 'jquery-global' vite plugin hack) — candidate for native b-form-select or vue-select. vue-typeahead-bootstrap — no Vue3 build, needs replacement. vue2-leaflet — replace with @vue-leaflet/vue-leaflet for Vue3. vue-awesome — no Vue3 release, replace with a maintained icon set (e.g. bootstrap-icons or @fortawesome/vue-fontawesome v3). bootstrap-select, bootstrap-fileinput, bootstrap-tokenfield, vue2-dropzone, vue2-editor, vuelidate(v0.7, Vue2-only, migrate to @vuelidate/core), vuex(migrate to Pinia per stack decision).

## Risks
- Duplicate-Bootstrap-4-compile pattern (app.scss + global/css/app.scss) means brand tokens are defined twice with DIFFERENT values ($brand-blue #0faca8 vs $brand #0394a6, different spacer maps, different theme-colors maps) — naive merge into one assets/css/main.scss in Nuxt will produce visible color/spacing drift versus production unless one system is chosen as canonical (recommend global/css/_variables.scss since it's the one already shared with Wiki and is closer to the actual live top-nav brand).
- $blue undefined-in-tree dependency on Bootstrap 4's default palette is a silent breakage risk: BS5's $blue differs slightly (#0d6efd vs #007bff), and if the new Nuxt app pulls Bootstrap 5 defaults without re-declaring $blue explicitly, every element using $blue (h1 color, nav links, footer links, status_title, footer h3, .textblue) will shift color with no compile error.
- b-btn (41 uses) and b-img-lazy (27 uses) have no direct bootstrap-vue-next equivalents — this is ~68 call sites needing manual rename/rebuild, concentrated risk of missed instances causing unstyled/broken buttons and images.
- b-form-datepicker (5 uses) has no bootstrap-vue-next component — any page with a date input (likely event scheduling/host forms) needs a net-new date-picker integration, a functional not just visual regression risk.
- vue-awesome (icon library, no Vue3 build) needs full replacement; every icon in migrated .vue components is a potential silent regression (wrong icon, missing icon, size/alignment shift) unless icons are audited component-by-component.
- Two independent top-nav implementations exist (sass/_navigation.scss vs global/css/components/_navigation-bar.scss) — migrating the wrong one, or merging them, risks recreating a nav that doesn't match either current page's actual rendered chrome; needs a screenshot/visual diff pass per page-type before cutover.
- Google Fonts loaded via @import url() twice today; if the Nuxt migration naively keeps two separate @import statements duplicated across component-scoped styles instead of one global load, FOUC/duplicate network risk persists or worsens under SPA route-level code splitting.
- MediaWiki's wiki.scss depends on resources/global/css/_variables.scss and bootstrap/bootstrap.scss staying present in the Laravel repo (via the legacyCssAliases vite plugin) even after the SPA split — if global/css/* is deleted or moved into the Nuxt app during cleanup, Wiki styling breaks silently since Wiki is out of migration scope but still consumes this CSS today.
- select2 requires the vite.config.js jquery-global hack (window.jQuery injection) to function under Vite/ESM — any select2-based UI (input-group with select2, tag inputs) ported to Nuxt needs either the same jQuery shim or full replacement (vue-select/vue-multiselect), not a drop-in port.

## Recommendations
- Treat resources/global/css/_variables.scss + components/_navigation-bar.scss + components/{buttons,forms,alerts,cards,tables,tabs,dropdown,pagination,row-columns}.scss as the seed for the new Nuxt assets/css/ global stylesheet — this is the umbrella brand layer already shared across products and closest to a canonical design system. Do NOT seed from resources/sass/app.scss's variables (legacy Fixometer-only palette) except where a value is actually used and has no global/css equivalent.
- Explicitly declare $blue (and any other implicitly-Bootstrap-sourced token) as a named brand variable in the new global stylesheet before importing Bootstrap 5, pinned to the CURRENT rendered value (#007bff) unless a deliberate rebrand is wanted — do not let it fall through to BS5 defaults.
- Self-host or centrally <link>-load fonts (Asap, Open Sans, Patua One) once in the Nuxt app.vue/nuxt.config rather than porting the @import url() CSS pattern — eliminates duplicate Google Fonts requests and improves control over font-display.
- Global stylesheet (assets/css/) should contain: brand color/spacing/typography variables, Bootstrap 5 variable overrides, top-nav (#navigation/.nav-wrapper equivalent, reconciled between the two current nav implementations — recommend rebuilding from global/css/_navigation-bar.scss), footer, base typography (h1-h3, .Font-* replaced with actual font-family utility classes or Bootstrap's own type scale), buttons, badges, alerts, form control base styling, table base styling, pagination.
- Page-specific stylesheets (_events.scss, _groups.scss, _dashboard.scss, _host.scss, _properties.scss, _reporting.scss, _networks.scss, _volunteers.scss, _onboarding.scss, _admin.scss) should become component-scoped <style scoped> blocks in their corresponding Nuxt page/component, not part of the global bundle — audit each for brand-variable dependence before porting.
- Component-specific styles (_card.scss, _modal.scss, _badge.scss, _list-group.scss, _accordion.scss, _panels.scss, _steps.scss, _slideshow.scss, _mini-stats.scss, _stat.scss, _table.scss) should map 1:1 to scoped styles on their bootstrap-vue-next replacement components.
- Dies with Blade entirely: resources/wiki/css/* (Wiki stays server-rendered MediaWiki, out of SPA scope), the legacyCssAliases vite plugin and its unhashed-path requirement, jQuery-dependent plugins tied to Blade/vanilla JS integration (select2's jquery-global shim, bootstrap-tokenfield, bootstrap-fileinput, bootstrap-select, bootstrap4-datetimepicker/tempusdominus) — replace with Vue3-native equivalents rather than porting the jQuery shims into Nuxt.
- Run a systematic grep-and-replace pass for data-toggle->data-bs-toggle, data-dismiss->data-bs-dismiss, class="close"->btn-close, sr-only->visually-hidden, badge-{variant}->text-bg-{variant}, input-group-append/prepend->input-group-text, as part of BS4->BS5 conversion — none of these are automatic via bootstrap-vue-next and all 29+13+10+4+9+4 = ~69 call sites need explicit review.
- Build a component-by-component bootstrap-vue -> bootstrap-vue-next mapping table before starting page ports, flagging the 4 known gaps explicitly: b-btn->b-button (rename), b-img-lazy->custom/native lazy loading (no replacement component), b-form-datepicker->third-party date picker (no bvn equivalent), b-select-> confirm b-form-select is the correct bvn name.
- Replace vue-awesome with an actively maintained Vue3 icon approach (e.g. bootstrap-icons via inline SVG or unplugin-icons) and keep the existing inline-Blade-SVG-partial pattern's assets (resources/views/partials/svg-icons/*.blade.php) as raw SVG source to port into Nuxt icon components — the SVG markup itself is framework-agnostic and reusable.
