# Findings: docker-ci

## Summary
restarters.net's current stack: Docker Compose (profiles core/debug/discourse) runs `restarters` (php-fpm app container that also self-hosts Vite dev server on :5173 and runs composer/npm/migrate on every start via docker_run.sh), `restarters_nginx` (nginx:latest, host :8001, fastcgi_pass to php-fpm:9000, serves both Blade+API same-origin), `restarters_db` (mysql:8.0), and a `playwright` container (mcr.microsoft.com/playwright, targets http://restarters_nginx). CircleCI (.circleci/config.yml, 247 lines) has exactly one monolithic `build` job (machine executor, ~35min setup wait + 45min phpunit + jest + 10min playwright, no Sonar step present) plus two Fly deploy jobs gated by branch (develop→dev, production→prod). Production (Dockerfile.fly) builds Vite assets and Laravel into one php-fpm+nginx+supervisord image serving everything on port 80 — no API/frontend split exists anywhere yet, and no CORS config exists since everything is same-origin today. Recommendations center on adding a new `nuxt` compose service modeled directly on Freegle's iznik-nuxt3 `freegle-dev-local` service (build context, NUXT_PUBLIC_API_BASE-style env, host port 3000), stripping nginx/Laravel down to API-only routes with explicit CORS config, adding parallel Taskfile tasks (docker:nuxt*, docker:test:vitest) and a separate CircleCI job (not extending the already-large `build` job) for Nuxt build+vitest+playwright, and deferring all Fly.io/production-topology redesign to adv-fly.

## Key facts
- docker-compose.yml (/home/edward/restarters.net/docker-compose.yml) defines profiles core/debug/discourse via COMPOSE_PROFILES; Taskfile.yml maps task docker:up-[core|debug|discourse|all] to `docker compose --profile X up -d`.
- App is served via nginx (docker/nginx.conf) reverse-proxying PHP to php-fpm on the `restarters` container port 9000 — NOT `artisan serve`. try_files $uri $uri/ /index.php?$query_string is the Laravel front-controller pattern; this is what an API-only Laravel would keep, just with all non-API routes removed/redirected.
- Vite (JS bundler) runs as `npm run dev` inside the restarters container itself (not a separate compose service), backgrounded by docker_run.sh, exposed on host port 5173 for HMR websocket. package.json (/home/edward/restarters.net/package.json): scripts dev=vite, build=vite build, production=vite build, test=playwright test, jest=jest --verbose. Deps: vue ^2.7.14, bootstrap-vue ^2.22.0, bootstrap ^4.6.1, @vitejs/plugin-vue2, laravel-vite-plugin ^0.8.1, vite ^4.5.0 — all Vue2/Bootstrap4/laravel-vite era, to be fully replaced by the Nuxt4/Vue3/bootstrap-vue-next stack.
- CircleCI config (.circleci/config.yml, 247 lines) has exactly one `build` job (machine executor ubuntu-2204:current, resource_class large) plus two deploy jobs (deploy-fly-dev on docker cimg/base:current, deploy-fly-prod same). Workflow build-and-deploy: `build` runs on all branches except production; deploy-fly-dev requires build and only runs on branch develop; deploy-fly-prod runs (independently, no `requires: build`) only on branch production.
- The single `build` job does, in order: checkout; install Task CLI; write .env from .env.example with sed substitutions (DB_HOST=restarters_db, DB_DATABASE=restarters_db_test, Discourse vars, APP_URL=http://localhost:8001, injects GOOGLE_API_CONSOLE_KEY/MAPBOX_TOKEN from CircleCI env); `task docker:up-all` (all profiles, CIRCLECI=true, COMPOSE_BAKE=true) with 10m timeout; a custom polling step waits up to 35 min for docker_run.sh's composer/npm/migrate cycle (detects crash-loop via RestartCount); Setup application step runs GRANT/SET GLOBAL sql_mode fixes on MySQL and `php artisan l5-swagger:generate`; Setup Discourse step inserts an API key row directly into Discourse's Postgres and calls `php artisan discourse:setting`; then three sequential test steps: `task docker:test:phpunit` (45m timeout), `task docker:test:jest` (no explicit timeout), `task docker:test:playwright` (10m timeout); then artifact/result collection via store_artifacts and store_test_results on /tmp/test-results.
- There is NO Sonar/SonarCloud job/step anywhere in .circleci/config.yml despite CLAUDE.md/memory mentioning SonarCloud elsewhere — Sonar analysis for this repo, if it exists, is configured outside CircleCI (UI-only per memory note) or not yet wired into this file.
- Taskfile docker:test:phpunit runs `./vendor/bin/phpunit -d memory_limit=1024M --coverage-clover tests/clover.xml --log-junit /tmp/phpunit-results.xml --teamcity`, uploads to Coveralls if COVERALLS_REPO_TOKEN set; skips local `migrate:fresh --seed` when $CIRCLECI is set (assumes CI already did it during docker_run.sh startup).
- Taskfile docker:test:jest installs jest-junit ad hoc and runs `npm run jest -- --testResultsProcessor=jest-junit`, writing JUnit XML to /tmp/test-results — this whole jest pipeline is what Vitest will replace for the Nuxt app.
- Taskfile docker:test:playwright is the most invasive step: clears app cache, truncates Device table via tinker, seeds a jane@bloggs.net admin user + NC/host/network/group fixture data via tinker one-liners, disables the `throttle:api` middleware via sed on Kernel.php, forces APP_DEBUG=false / QUEUE_CONNECTION=sync / MAIL_MAILER=log via sed on .env, kills the dev Vite process and runs `npm run build` (production assets) — Playwright never tests against Vite HMR, always against a built bundle — then in the `restarters_playwright` container runs `npx playwright install chromium` and `npx playwright test --reporter=html` with PLAYWRIGHT_BASE_URL=http://restarters_nginx.
- playwright.config.js (/home/edward/restarters.net/playwright.config.js): workers:1 (avoids CSRF collisions — a constraint the Nuxt SPA + API-only backend may relax if CSRF handling changes to token/header-based auth), testDir 'tests/Integration', outputDir /tmp/test-results, baseURL defaults to http://restarters_nginx (Docker network hostname, port 80) overridable via PLAYWRIGHT_BASE_URL env, trace/screenshot/video always on, timeout 5 min/test, retries 2, single project 'Desktop Chromium' (other browsers commented out as unreliable), excludes one slow autocomplete test via grep.
- Dockerfile.fly production build stage 1 is php:8.2-cli + Node 18, runs `composer install --no-dev`, `npm ci --legacy-peer-deps`, generates a dummy .env with random APP_KEY for build-time artisan commands (lang:js, package:discover), then `npm run production` (vite build) and `l5-swagger:generate`; stage 2 is php:8.2-fpm + nginx + supervisord + cron, copies the built app (with public/build assets) from stage 1, single container serves everything on port 80 behind Fly's http_service. This conflates API + frontend serving in one image/one Fly app — a Nuxt split will need either (a) a second Fly app/container for the Nuxt SSR/static output, or (b) building Nuxt as static and having this same nginx serve it from a different path while Laravel becomes pure API. That production-deploy redesign is explicitly out of scope here, only flagged.
- fly.toml / fly.dev.toml env vars include VITE_MANIFEST_PATH=public/build/manifest.json (Laravel's asset() helper reads this to inject built CSS/JS tags into Blade — will become dead/removable once Blade views are retired in favor of API+Nuxt), SESSION_DOMAIN=.restarters.net (cookie-domain-based session auth — relevant to CORS/credentialed-fetch design for the SPA), APP_URL=https://restarters.net.
- Reference pattern from sibling project /home/edward/FreegleDockerWSL/docker-compose.yml (Nuxt3 SPA/SSR container 'freegle-dev-local', lines 1018-1065): built via `build: {context: ./iznik-nuxt3}`, host port mapped (3002), env vars IZNIK_API_V2=<api base url>, NITRO_PRESET=node-server, NUXT_DEV_MODE=true, NODE_ENV=development, NUXT_BUILD_MODE=development, TEST_BASE_URL=http://127.0.0.1:3002 — i.e. the API base URL and the SPA's own origin are both injected as container env vars, and Playwright/tests target TEST_BASE_URL pointed at the Nuxt container directly (not proxied through a shared nginx) in that repo. Directly transferable pattern for restarters' new nuxt-dev service.

## Inventory
- **restarters (app container)**: Dockerfile at repo root, FROM php:8.2-fpm. Built with UID/GID build args to match host user. Runs docker_run.sh as CMD which: copies .env.example if missing, `composer install`, rewrites DB_HOST/DB_DATABASE/SESSION_DOMAIN/DISCOURSE_URL/DISCOURSE_SECRET in .env, waits for MySQL, `php artisan migrate:fresh --seed`, `npm install --legacy-peer-deps`, `npm rebuild node-sass`, starts `npm run dev` (Vite) in background writing /tmp/vite.log, `php artisan key:generate`, `cache:clear`, `config:clear`, `l5-swagger:generate`. Listens on php-fpm port 9000 (not HTTP directly). Code bind-mounted from repo root to /var/www:rw. Exposes host port 5173 for Vite HMR client connections.
- **restarters_nginx**: image nginx:latest, container_name restarters_nginx, maps host 8001->80. Mounts docker/nginx.conf and ./public (read-only) into /var/www/public. Proxies PHP requests via fastcgi_pass restarters:9000 (unix TCP to php-fpm in the app container). This is the entrypoint used by both browser dev access (http://www.example.com:8001) and Playwright's PLAYWRIGHT_BASE_URL.
- **restarters_db**: mysql:8.0, container_name restarters_db, DB restarters_db_test, user restarters/s3cr3t, root s3cr3t. Exposed internally on 3306 only (not host-mapped). my.cnf mounted from ./mysql/my.cnf.
- **phpmyadmin / mailhog**: profile 'debug' only. phpMyAdmin on host 8002, Mailhog web UI on host 8026 / smtp 1025.
- **playwright container**: image mcr.microsoft.com/playwright:v1.55.1-noble, container_name restarters_playwright, code bind-mounted to /var/www, depends_on restarters_nginx, env PLAYWRIGHT_BASE_URL=http://restarters_nginx (i.e. tests hit nginx by Docker DNS name, port 80 internal, not host 8001). Command installs chromium then idles (`tail -f /dev/null`); actual test run is triggered later via `docker exec` in Taskfile/CI.
- **Discourse stack**: profile 'discourse': postgresql (bitnamilegacy/postgresql:11), restarters_discourse_redis, restarters_discourse (bitnamilegacy/discourse:2, host port 8003), sidekiq worker. Only relevant to SSO/Discourse feature testing, unrelated to Nuxt migration except CORS/session concerns.
- **Dockerfile.fly / fly.toml / fly.dev.toml**: Multi-stage prod image: builder stage (php:8.2-cli + Node 18) runs composer install, npm ci --legacy-peer-deps, `npm run production` (vite build), l5-swagger:generate, then copies dist into php:8.2-fpm+nginx+supervisord runtime image (nginx-fly.conf, supervisord-fly.conf, cron for scheduler/queue-watchdog/backups). fly.toml env includes VITE_MANIFEST_PATH=public/build/manifest.json, SESSION_DOMAIN=.restarters.net, APP_URL=https://restarters.net. Single Fly app serves both API and built Blade/Vite frontend from same container/port 80.

## Risks
- workers:1 in playwright.config.js exists specifically to avoid CSRF issues with Laravel's session-based CSRF token; moving to an API-only Laravel with a Nuxt SPA changes the auth/CSRF model (likely Sanctum SPA cookie auth or token-based) — this constraint should be re-evaluated, not blindly carried over, since it currently caps Playwright parallelism and inflates CI time.
- Playwright currently always tests against a `npm run build` production bundle of Vite assets (docker:test:playwright kills the Vite dev server and rebuilds) — for Nuxt, decide explicitly whether CI Playwright runs against `nuxt build && nuxt preview`/node-server, or against `nuxt dev`; the Freegle pattern (NUXT_DEV_MODE=true, TEST_BASE_URL) suggests they test against dev-mode Nuxt directly, which is a different tradeoff (faster CI, less production-fidelity) than restarters' current Vite-production-build approach.
- The single CircleCI `build` job already routinely waits up to 35 minutes just for docker_run.sh (composer+npm+migrate) before any tests start, then 45m phpunit + jest + 10m playwright — total job is already CI-time-sensitive; naively adding a Nuxt build + vitest + a second Playwright pass in the same serial job risks blowing past CircleCI's default job timeouts and makes the single job even more of a bottleneck. Splitting into parallel CircleCI jobs (fan-out from a shared checkout/workspace) is strongly advisable rather than extending the existing monolithic `build` job.
- nginx (docker/nginx.conf and docker/nginx-fly.conf) currently has a catch-all `try_files $uri $uri/ /index.php?$query_string` — becoming API-only means every route classification (which paths are `/api/*` vs everything else) must be decided; in dev, the Nuxt container will own the non-API routes/HMR and nginx (or Nuxt's own dev server) must not fight over paths. In prod (Dockerfile.fly), the single supervisord/nginx image currently serves Blade+assets on the same port as the API — this is the piece flagged, not designed, for later rework.
- CORS: today nginx/Laravel serve everything same-origin (nginx:8001 for both app and API), so no CORS layer exists yet. Introducing a separate Nuxt origin (e.g. host port 3000) talking to Laravel's API (nginx:8001 or a new /api-only port) will require explicit CORS middleware config (config/cors.php) with allowed origins for dev (http://localhost:3000 or similar) and Sanctum stateful domains if cookie-based auth is kept — currently absent from the codebase as far as these files show.
- SESSION_DOMAIN=.restarters.net and cookie-domain-scoped sessions in fly.toml imply session-cookie auth; if the Nuxt SPA and API end up on different subdomains/ports even in prod, SESSION_DOMAIN and SameSite/Secure cookie attributes need revisiting for cross-origin credentialed requests — a security/session design decision to flag to adv-sec.
- docker_run.sh chains composer install + npm install + migrate:fresh --seed + npm run dev on every container start/restart; a Nuxt container should NOT copy this pattern wholesale (it makes cold starts extremely slow, already causing the 35-minute CI wait) — a leaner Nuxt entrypoint (npm ci once via image build layer caching, `nuxt dev` directly) is preferable.
- No SonarCloud step found in .circleci/config.yml despite user memory referencing SonarCloud config for this repo — verify separately (possibly a GitHub Action or Sonar's own CI-independent auto-analysis) before assuming CircleCI needs a Sonar job added for Nuxt code; don't duplicate.

## Recommendations
- docker-compose.yml: add a new service `nuxt` (or `restarters_nuxt`) with profiles ["core","debug","discourse"] so it starts alongside the existing stack. build: {context: ./restarters-nuxt (or wherever the new repo/dir lives), dockerfile: Dockerfile} mirroring Freegle's iznik-nuxt3 Dockerfile pattern. Map host port e.g. 3000:3000. Mount source as volume for HMR (`./restarters-nuxt:/app:rw` with an anonymous volume over node_modules to avoid host/container node_modules clashes, matching common Nuxt-in-Docker practice). depends_on restarters_nginx (or a new API-only nginx) with condition service_started.
- Env vars for the nuxt service, mirroring Freegle's freegle-dev-local: NUXT_PUBLIC_API_BASE=http://restarters_nginx (server-to-server, Docker network) plus a browser-facing one like NUXT_PUBLIC_API_BASE_CLIENT=http://localhost:8001/api (what the browser actually calls) — decide SSR vs SPA-only early since restarters is being built as a pure SPA (per task framing), so likely NITRO_PRESET=static or just `nuxi dev`/`nuxi generate`; NODE_ENV=development; TEST_BASE_URL=http://127.0.0.1:3000 for Playwright.
- nginx: keep restarters_nginx serving ONLY the Laravel API going forward — strip the Blade catch-all (`try_files ... /index.php`) down to `/api` (and any needed non-API endpoints like Discourse SSO callback, webhooks) once Blade views are retired; the Nuxt container's own dev server (or a second nginx in front of it) becomes the entrypoint for browser-facing routes. In dev, simplest is: browser hits Nuxt directly on :3000, Nuxt calls Laravel API on :8001/api with CORS enabled — no shared-nginx-frontend needed in dev, unlike Freegle's Traefik setup (restarters doesn't currently use Traefik, so don't introduce it just for this; keep the existing nginx+profiles model).
- config/cors.php (Laravel): add allowed_origins for http://localhost:3000 (dev), the future Nuxt prod origin, and Capacitor's origin scheme (capacitor://localhost / http://localhost for Android WebView) proactively since a Capacitor app is anticipated — set supports_credentials true only if staying with cookie/Sanctum auth; otherwise plan a token-based (Sanctum personal access tokens or Passport) auth so CORS can be simpler and credential-free, which also plays better with Capacitor's non-browser-cookie-jar environment. Flag this specific decision (cookie-session vs token auth) to whichever agent owns the API auth design — it's the crux of both the CORS work and future mobile support.
- Taskfile.yml: add tasks docker:nuxt (foreground `npm run dev` in the nuxt container, mirroring docker:vite), docker:nuxt:start/docker:nuxt:stop (background variants, mirroring docker:vite:start/stop), docker:test:vitest (mirroring docker:test:jest — run vitest with JUnit reporter output to /tmp/test-results for CI parity), and either extend docker:test:playwright or add docker:test:playwright:nuxt pointing PLAYWRIGHT_BASE_URL at the nuxt container/port instead of restarters_nginx. Keep the existing docker:test:playwright targeting the legacy Blade app until it's fully decommissioned, to allow incremental cutover route-by-route.
- CircleCI: split the current single `build` job into parallel jobs sharing setup via workspace or by simply running two independent machine-executor jobs from the same checkout (cheaper than fixing/orchestrating workspace persistence given docker-in-docker): (1) existing `build` job trimmed to just Laravel API concerns (phpunit + legacy jest/playwright while the old frontend still exists) and (2) a new `build-nuxt` job that does `task docker:up-core` (just Laravel API + DB, skip Discourse/debug), builds/starts the nuxt container, runs `task docker:test:vitest`, then `task docker:test:playwright` against the Nuxt container. Both feed into deploy-fly-dev/deploy-fly-prod via `requires`. This avoids inflating the already-45min+35min `build` job further and lets Nuxt-only changes get faster feedback.
- For CI time: prefer `nuxt build && nuxt preview`-style static/node-server serving for the Playwright run (matches production more closely than dev mode) but cache the Nuxt build layer aggressively (Docker layer caching keyed on package-lock.json, same pattern already used in Dockerfile.fly's builder stage for composer/npm) to keep the added CI job under roughly 10-15 minutes; do not reuse docker_run.sh's pattern of npm install on every container start inside CI — bake `npm ci` into the image build step instead so CircleCI's `docker:up-all`-style start is fast.
- Playwright: create a second playwright config (e.g. playwright.nuxt.config.js) or parametrize testDir/baseURL via env so legacy Blade Playwright specs (tests/Integration) and new Nuxt specs (e.g. tests/nuxt/Integration) can run independently and be retired incrementally; re-evaluate `workers: 1` once the new API's CSRF/auth model is decided — if token-based, parallel workers likely become safe, cutting Playwright CI time.
- Flag to adv-fly (not design here): Dockerfile.fly and fly.toml/fly.dev.toml currently build and serve Blade+Vite assets from the SAME container/port as the API (VITE_MANIFEST_PATH env, nginx-fly.conf catch-all). Eventual production topology needs either a second Fly app for the Nuxt output (static `nuxt generate` deployed to a CDN/Fly static app, or a Node/Nitro server as a second Fly app) or folding Nuxt's static build into the existing nginx-fly.conf as a separate location block while Laravel drops to /api only — this is a deploy-architecture decision, intentionally left to adv-fly.
- Playwright container: mirror Freegle's Dockerfile.playwright approach only if Nuxt-specific browser deps diverge from the existing mcr.microsoft.com/playwright:v1.55.1-noble image already in docker-compose.yml; otherwise reuse the existing `playwright` service (it's already generic, keyed off PLAYWRIGHT_BASE_URL) rather than adding a duplicate container — just point it at the Nuxt origin for the new test suite via a second `docker exec` invocation with a different PLAYWRIGHT_BASE_URL/testDir, saving image pulls and container count.
